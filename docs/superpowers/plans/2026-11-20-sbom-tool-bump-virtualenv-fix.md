> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bump the dev-only SBOM generator `cyclonedx-bom` to 9.x to lift the transitive `packaging<26` cap, re-attest the release SBOM against it, and lock in the `virtualenv ≥ 21.14.9` advisory fix — with the runtime lock and SBOM component set unchanged.

**Architecture:** A dev-dependency + committed-artifact refresh. No runtime code or runtime lock changes; three dev-only packages move (`cyclonedx-bom`, `virtualenv`, transitively `packaging`), the committed `sbom/` artifacts are regenerated by the new generator, and the sign-off doc is updated. The existing `tests/test_sbom.py` gate is the regression proof that re-attestation stayed reproducible/complete/well-formed.

**Tech Stack:** Python 3.12, `.venv/bin/python`, pip-tools (`pip-compile`), `cyclonedx-bom` (`cyclonedx-py` CLI), `pip-audit`, pytest.

**Spec:** docs/superpowers/specs/2026-11-20-sbom-tool-bump-virtualenv-fix-design.md

## Global Constraints

- `requirements.txt` (the runtime lock) stays **byte-identical** — `git diff --exit-code requirements.txt` must be clean at every commit. All three bumped packages are dev-only.
- `src/secure_ai_research/retrieval/authz.py` and `research_service.py` stay **byte-untouched**; no runtime-path behaviour change.
- `cyclonedx-bom` pinned `>=9.0,<10.0`; `virtualenv` floor `>=21.14.9` — exact values, in `pyproject.toml`'s dev extra.
- The release SBOM keeps the same **24 runtime components**; the digest stays the `{name,version,purl}` projection (prior-slice D1 scope, unchanged).
- Hermetic suite green: `./.venv/bin/pytest -q -m "not integration"`. Integration: `-m integration`.
- SBOM generation stays **offline** and **reproducible** (raw-byte-identical across runs) under 9.x.

## Review Focus

- **Runtime lock + SBOM component set unchanged.** A moved `requirements.txt` pin or a component_count ≠ 24 would silently alter the committed release artifact. (Task 1 `git diff --exit-code`; Task 2 count assertion.)
- **Reproducibility holds under 9.x.** A newer serializer could reintroduce a timestamp / `serialNumber` / ordering nondeterminism, making the drift gate flap. (Task 2 `test_release_sbom_is_reproducible`, run twice.)
- **SBOM generation stays offline under 9.x.** A newer `cyclonedx-py` that reaches a vuln DB or PyPI breaks the deterministic/offline posture. (Task 2 offline re-verify step.)
- **The advisory actually clears.** `virtualenv ≥ 21.14.9` must cover the full `PYSEC-2026-4374..4383` range, confirmed by `pip-audit` on the dev set — not merely a higher version number. (Task 1.)
- **The dev re-lock introduced no new conflict / silent downgrade.** `packaging 25→26.x` must not break another dev tool capped `<26`. (Task 1 `pip-audit` + Task 2 full suite.)

### Task 1: Bump the SBOM generator + virtualenv, re-lock the dev set

**Interfaces:**
- Produces: a dev lock pinning `virtualenv>=21.14.9` and `cyclonedx-bom` 9.x, with `cyclonedx-py` 9.x installed in `.venv` (Task 2 regenerates the SBOM with it).

- [ ] **Step 1: Write the failing test** — `tests/test_dev_lock.py`

```python
import re
from pathlib import Path
from packaging.version import Version

_LOCK = Path(__file__).resolve().parents[1] / "requirements-dev.txt"

def _pinned(name: str) -> Version:
    m = re.search(rf"(?mi)^{re.escape(name)}==([^\s;]+)", _LOCK.read_text(encoding="utf-8"))
    assert m, f"{name} not pinned in requirements-dev.txt"
    return Version(m.group(1))

def test_virtualenv_advisory_is_fixed():
    # PYSEC-2026-4374..4383 fixed in 21.14.9
    assert _pinned("virtualenv") >= Version("21.14.9")

def test_sbom_generator_major_is_9x():
    v = _pinned("cyclonedx-bom")
    assert Version("9.0") <= v < Version("10.0")
```

- [ ] **Step 2: Run the test to verify it fails**

Run: `./.venv/bin/pytest tests/test_dev_lock.py -q`
Expected: FAIL — `virtualenv` is 21.14.5 (< 21.14.9) and `cyclonedx-bom` is 5.5.0 (not 9.x).

- [ ] **Step 3: Lift the caps in `pyproject.toml`**

In the `dev` optional-dependency list: change the `cyclonedx-bom` specifier to `>=9.0,<10.0`, and add/replace a `virtualenv>=21.14.9` entry. Leave every other dev entry and all of `[project].dependencies` (runtime) untouched.

- [ ] **Step 4: Re-lock the dev set**

Expected: resolves successfully (cyclonedx-bom 9.x lifts the `packaging<26` cap, so `virtualenv ≥ 21.14.9` + `packaging ≥ 26.3` co-resolve). Then install it: `./.venv/bin/pip install -r requirements-dev.txt`.

- [ ] **Step 5: Run the test to verify it passes**
